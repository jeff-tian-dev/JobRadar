SENTENCE STRUCTURE — this is the most important rule.

Every `new_text` must follow ONE of these three patterns. Pick the pattern that fits the original bullet's content best, and vary patterns across the 2 edits in the same project so they don't sound identical.

Each pattern has the same skeleton: **ONE main verb, ONE outcome/scope, ONE supporting prepositional phrase.** Nothing else. No relative clauses ("which", "that", "where"), no compound predicates ("X and Y …"), no second main verb, no parenthetical asides, no appositive commas, no "showing/demonstrating" suffixes.

──── Pattern A — Action + Outcome + via/with + ONE Tool ────
Form: «Verb» «scope/outcome» via/with «one tool or method».
Use when the original bullet leads with a build action.
Examples (each is a single clause, no commas, ends in a period):
  - "Cut recurring LLM API spend to $0 via local Ollama inference."
  - "Shipped a 10-page React SPA on Oracle Cloud via GitHub Actions CI/CD."
  - "Packaged the desktop controller with PyInstaller for standalone distribution."

──── Pattern B — Outcome (with metric) + by + ONE Method ────
Form: «Outcome verb + metric» by «one method or tool».
Use when the original bullet has a clear time/cost/scale saving.
Examples:
  - "Reclaimed ~3–7 hrs/week by automating UI cycles with OpenCV template matching."
  - "Saved ~5–8 hrs/week of manual war audits via scheduled systemd-timer ingestion."
  - "Eliminated manual feed polling by running a daily discovery job under launchd."

──── Pattern C — Verb + Scale + ONE Scope Detail ────
Form: «Verb» «scale/count» «one scope/coverage detail».
Use when the original bullet's main fact is a number or scope (test count, row count, route count).
Examples:
  - "Implemented 90+ pytest tests covering HTTP, LLM mocking, and dedup logic."
  - "Managed 20k+ rows across 13 incremental SQL migrations in Supabase."

STRUCTURAL CHECKLIST — every `new_text` must pass all of these:
  ✓ One sentence, one period, ends in a period.
  ✓ Exactly one main verb (count past-tense verbs at the start of clauses; if you have two, you have two main verbs — wrong).
  ✓ At most ONE supporting phrase (the «via/with/by/for» tail). No second tail clause.
  ✓ Zero relative clauses: no "which", "that", "where", "while", "ensuring", "providing", "delivering" as a hanging participial.
  ✓ Zero "and …and…" chains. At most one comma, used only for a 2- or 3-item list inside a single phrase (e.g. "covering HTTP, LLM mocking, and dedup logic"). Never use a comma to join two clauses.
  ✓ No JD meta-commentary ("addressing the JD's", "aligning with the role's", "for the AI Platform team").
  ✓ Banned filler — instant rewrite if present: "demonstrating", "showcasing", "proving", "showing proficiency", "highlighting", "ensuring code quality", "delivering scaled solutions", "passion for", "ability to", "for robustness", "for scalability", "for analytics", "for development tasks".

If a sentence passes the checklist, it is automatically the right length (~85–115 chars). You do NOT need to count characters — let the structure constrain the length. **Hard backstop: 125 characters max.**
